v10 — CARE-LG on a Third Dataset real data, cardio, 5 seeds

The full CARE-LG architecture (type-aware VAE, Riemannian pullback-metric graph search, B1/B2-fixed hard clinical-constraint gate, per-age-bracket target definition, certified-infeasibility check, Stage 2 synthetic fallback) run top-to-bottom on the Kaggle Cardiovascular Disease dataset (70,000 raw rows; 20,000-row stratified subsample per seed for computational tractability — disclosed scoping decision, see experiments_v10/data_cardio.py) instead of UCI Heart or Real NHANES. Separate experiment tree (experiments_v10/), src/ untouched; Stage 1's target definition and Stage 2's algorithm are reused unmodified from scripts/run_age_stratified_experiment.py and scripts/run_stage2_synthetic_search.py. Stage 1's path search uses find_path_sra (src/graph/source_relative_admissibility.py) — a first cardio run using the older find_path_augmented came back with a nonzero real CVR (~1.5%), the same compositional constraint-drift leak found and fixed earlier this project, now confirmed on a third, independent dataset; this report reflects the SRA-fixed rerun.

Provenance caveat, disclosed not hidden: this dataset's origin is an uncredited Kaggle upload (no cited clinical institution), and, like every CLINICAL_EFFORT_WEIGHTS dict in this project (see configs/dataset_config.py's own note on 'uci'/'nhanes'), the cost weights in experiments_v10/data_cardio.py are freshly invented, illustrative constants, not derived from a published treatment-burden instrument.

Real-value CVR

0.00% on all three datasets, by construction, using the SRA-fixed search (find_path_sra). A first cardio run using the pre-fix find_path_augmented measured ~1.5% real CVR — the compositional constraint-drift leak (two admissible-looking hops compounding into a real endpoint violation neither hop's own check catches) reproducing on this third, independent, much larger dataset. That is useful evidence the vulnerability is dataset-general, not a UCI/NHANES quirk — and confirmation the fix generalizes too, since it closed it here as well.

Honest read

The headline number is mostly a scale artifact, not a methodological win. Stage 1 success here (99.4%) is far higher than UCI (38.5%) or NHANES (50.9%) primarily because the low-risk training pool is much larger (4,000 vs. NHANES's ~909, UCI's ~60) — the same dynamic this project's own threshold-sensitivity sweep already showed: a denser target pool makes reaching SOME admissible low-risk patient trivially easier, independent of any change in search quality. This should not be read as "the model got dramatically better" on cardio; it is a property of the dataset's scale, stated plainly rather than left implicit. A secondary factor: cardio's features are almost entirely directional lifestyle factors (weight, BP, cholesterol/glucose category, smoking/alcohol/activity) with no age-horizon cap comparable to UCI/NHANES's continuous labs.

Two disclosed simplifications: height was dropped entirely (see experiments_v10/data_cardio.py, same category as v8 dropping age) rather than forced into the type-aware VAE's high-cardinality categorical decoder head, and cholesterol/glucose are 3-level ordinal categories in the source data, not continuous mg/dL values — weaker signal than UCI's continuous cholesterol, directionally usable regardless.
